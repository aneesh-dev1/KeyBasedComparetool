STRUCTURED DATA

JSON comparison

Compare nested objects and arrays. Object property order is always ignored. Strings are case-sensitive, types matter, and duplicate array items remain significant. Numbers compare by numeric value.

Paste JSON or load UTF-8 files. Maximum 5 MiB per input, 100 nesting levels, and 200,000 values. JSON results are kept in this tab until you refresh; download a report to retain them.

Array rules

Override the default for a specific array. Use $ for a root array, $.customers, or $.customers[*].addresses. Use $["property.with.dots"] for special property names. Match fields are direct properties, such as id.

Without a match field, changed blocks in unordered arrays appear as removed and added. Match fields must be unique and non-null within each array.

Preview shows the first 200 differences with values shortened to 1,000 characters. Downloads contain all results. Paths refer to original positions in each input. More than 10,000 differences returns an error rather than a partial report.

EXCEL WORKSHEETS

Select sheets to compare

Choose one worksheet from each Excel workbook. The first row must contain unique, nonempty column names. Only selected sheets are imported.

Excel uses stored values, not display formatting. Text and leading zeros stored as text are preserved. Numeric dates are compared as Excel serial numbers; booleans become TRUE/FALSE. Cached formula results are used without recalculation; missing results cause an error. Completely blank data rows are skipped. Macros are never executed.

Matching rows are excluded from both files before sorting and comparison. Key values remain case-sensitive; leading zeros matter.

For a 32 GB machine, start with 4 GB and parallel sorting on a local SSD. The budget is shared across sort workers; it is not a hard limit on total RAM. Use sequential sorting on a slow disk.
